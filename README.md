# ESP-12F 空调温控

本工程使用 ESP8266 RTOS SDK 3.4，实现两组温度规则、红外学习与发送及手机配置页。GPIO4 接 DS18B20，GPIO5 接 HS0038B，GPIO14 驱动红外 LED；S1/GPIO12 控制配置热点，S2/GPIO13 关闭热点并进入自动休眠，继续定时温控。项目使用单手机配置，不涉及多客户端。

最近正式本地发布为 **0.1H（2026-10-06，160 MHz）**；当前工作区包含后续 80 MHz、休眠诊断、定时器暂停和温度校准改动，未另设发布编号。发布内容、产物和验证见 [本地发布](#本地发布)，历史变更通过 `git log` 查询。接线见 [硬件说明](ESP-12F硬件引脚与链路说明.md)，开发约定见 [CLAUDE.md](CLAUDE.md) 和 [AGENTS.md](AGENTS.md)。

## 手机配置

1. 按 S1 开启热点，连接开放 Wi-Fi `空调智能温控`。未自动弹页时访问 `http://192.168.4.1`。
2. 设置两组规则的触发温度（−10～50 °C）、升温或降温方向，保存规则。
3. 点击对应组的“学习红外”，在 15 秒内按一次遥控器目标按键；学习成功后先用“测试发送”验证，再启用并保存规则。
4. 两组共用红外发送频率（36/38/40 kHz，默认 38 kHz）。修改后保存到 NVS，并影响所有已学习编码的后续发送。HS0038B 不能测出遥控器载波频率，需用目标空调验证兼容性。

学习码写入并提交 NVS 后，会读回逐字节核对；核对失败不显示学习成功，当前内存中的旧编码保留，但已提交的 Flash 内容需重新学习确认。学习成功、开机加载及发送完成日志均记录 `code=` 内容校验值，同一组可据此对比重启或休眠前后是否变化。启动时缺失或无效的 NVS 编码会明确记录。默认 `python flash.py` 分段烧录不覆盖 NVS；整片烧录 `full_flash.bin` 或擦除 Flash 会清除保存的数据。编码仍在但空调无响应时，还需核对学习波形及实际发射。

## 温度测量与校准

当前接法按用户确认：外置裸 DS18B20、VDD/DQ/GND 三线供电、DQ 使用 4.7 kΩ 上拉、引线不超过 1 米。相邻显示变化 0.1～0.2 ℃本身不能证明绝对误差超标。目标是在 18～30 ℃内实测误差不超过 ±0.5 ℃，±0.3 ℃仅作为改善目标；[DS18B20 官方数据手册](https://www.analog.com/media/en/technical-documentation/data-sheets/ds18b20.pdf)给出的 −10～85 ℃精度为 ±0.5 ℃，12 位分辨率为 0.0625 ℃。本轮没有参考温度计对照数据，默认偏移为 0，不加滤波或控制回差。

先固定探头在通风处，避开主板、电源、充电电路、日晒及空调直接出风，避免手持；检查接点与探头端供电，若探头端没有去耦，在 VDD/GND 附近增加 100 nF 电容。参考温度计的已知准确度须优于 ±0.2 ℃，两探头靠近但不接触，保持相同高度和气流，裸传感器不直接浸水。热平衡至少 15 分钟且参考读数稳定后，连续记录 10 分钟配对数据；分别对照热点开启、关闭及 USB 充电状态，记录平均偏差、波动范围和读取失败次数。建议记录列为时间、参考温度、`raw16`、`temperature10`、AP/充电状态和错误；`raw16 / 16` 为未校准摄氏温度。现场安装、去耦、参考仪器及这些测量均尚未核验。

若误差达标，保留零偏移。若偏差随热点或充电状态明显变化，先解决安装受热，不能用固定偏移补偿；只有热平衡后的稳定偏差才做单点校准。在约 25 ℃求 `偏移℃ = 平均参考温度 − 平均原始温度`，四舍五入为 0.1 ℃的整数填入根目录生成配置 `sdkconfig` 的 `CONFIG_APP_TEMP_OFFSET10`，再执行 `python build.py`。例如参考为 25.0 ℃、原始平均为 25.3 ℃时设为 `-3`，即减 0.3 ℃。范围为 −50～50（±5.0 ℃），不是允许误差；明显大偏差应先排错。`sdkconfig.defaults` 默认值为 0，不覆盖已有 `sdkconfig`，构建后须核对 `build\auto\config\sdkconfig.h` 的实际值。偏移不写入 NVS，不增加网页设置或 HTTP API。

固件在原始 1/16 ℃读数上应用偏移后，仅做一次四舍五入到 0.1 ℃；显示与规则判断共享同一结果。每次转换前读取并 CRC 校验 scratchpad 的分辨率，只有低于 12 位时才保留 TH/TL 并修正 RAM，读回确认后启动转换，不写传感器 EEPROM。核验/读回失败上报错误并阻止本次控制；结束读取仍保留 CRC/设备未找到最多三次重读、85 ℃默认值拒绝及 GPIO 清理错误上报，转换后分辨率变回低位也拒绝该读数。日志 `raw16`、`resolution=12`、`offset10`、`temperature10` 用于追踪原始与校准结果；这些日志表示有效 scratchpad 已解码，最终成功还要求总线清理成功。静默 UART 配置下不输出运行诊断。

校准后在约 18 ℃、30 ℃独立复核，并在三个温点分别检查热点开启/关闭、充电状态及休眠恢复后的读数与规则触发。仅在参考稳定的区间评估，配对温度误差须不超过 ±0.5 ℃；记录失败数量和原因，不将失败或缺失读数计作成功。若多温点仍不能达标，停止追加补偿，换用可追溯来源的 DS18B20 后重新核验。软件测试不能代替此项实机精度验收。

## 电池电压

电压随测温采集，使用 `adc_read` 单次读取，按当前板实测参考做单点增益校准；返回值超出 0～1023 时报错，不额外开启 RF。页面每 2 秒刷新、显示两位小数，刷新不增加采样频率。日志的 `measured` 仍保留按 330 kΩ / 82 kΩ 名义分压换算的未校准值。

依据用户报告电池端稳定 3.994 V 及 2026-10-06 14:09～14:10 日志，冷启动参考 ADC 为 843，AP 开启六次平均为 839.5，休眠唤醒两次平均为 909.5。换算为 `battery_mV = round(adc × 3994 / reference_adc)`，使用整数运算保留原始 ADC 的变化；取代此前 101/111 临时补偿。AP 开启使用 AP 参考，AP 关闭且经历允许自动休眠的等待后使用 sleep 参考，其余使用 boot 参考。这是允许休眠的状态标记，不证明实际已经入睡。

日志保留 `adc`、`measured`、`compensated`，新增 `cal=boot/ap/sleep`；`compensated=1` 只表示选用 sleep 校准分支，所有分支都做校准。页面和低电量判断使用校准后电压：低于 3.5 V 提示，达到 3.5 V 隐藏；读取失败显示错误，不影响温控。当前系数针对本板、当前构建及 3.994 V 附近，其他板、回退 160 MHz 或其他电压点应重新实测；ADC 状态差异根因及全电压范围精度未确认，低电量点还需独立核验。

## 运行行为

| 状态 | 测温与控制 | 指示灯 |
| --- | --- | --- |
| 开机、热点关闭 | 开机立即测温，之后每 30 秒测温并检查规则 | 熄灭 |
| 热点开启 | 每 2 秒测温并检查规则 | 每秒亮 500 ms |
| S2 休眠温控 | 关闭热点，每 30 秒测温并检查规则，间隔允许自动 light sleep | 熄灭 |

S1 可提前关闭热点；红外学习或发送期间将关闭请求延后到红外空闲，再按 S1 可取消待处理请求。休眠中 S1、S2 均通过 GPIO 唤醒：S1 开关 Wi-Fi 热点，S2 快速关闭热点并返回休眠温控。S2 关闭热点后继续每 30 秒采温和按规则发送红外；重复按 S2 不暂停温控、不清空规则状态，S1 可重新开启热点。红外忙碌时，S2 关闭请求延后到空闲；关闭失败会上报错误，温控继续，但不能保证进入休眠。DS18B20 转换期间的按键需等待约 750 ms 加一个 FreeRTOS tick 后处理；长按只产生一次操作。热点关闭失败会记录错误，保留状态供再次操作。

热点开启后，未访问控制页或操作配置 API 时，3 分钟后关闭；使用后从最后一次上述操作起空闲 10 分钟关闭，自动回到休眠温控。状态轮询、系统探测及后台请求不延长期限；红外忙碌时延后关闭。

每次有效采温直接判断启用的规则：升温方向在温度大于等于阈值时满足，降温方向在温度小于等于阈值时满足；首次满足立即发送，无需先跨越阈值。持续满足时，每组距离上次成功自动发送至少 120 秒才再次发送，按下一次有效采样执行；两组独立计时，S2、正常休眠、修改规则及测温错误不清空发送间隔。条件不满足、规则未启用、未学习红外或正在学习时不自动发送；测温失败仅阻止本次发送，恢复有效读数后重新判断。自动发送失败不计入成功间隔，后续采样可重试；网页测试发送不受此自动间隔限制。30 秒采样可能漏掉两次采样之间的短暂越界，也可能使重复发送晚于 120 秒。

## 红外与诊断

GPIO5 接收输入启用内部上拉，初始化时关闭边沿中断；仅安装学习回调后开启双边沿，学习结束、超时或出错时先在临界区关闭硬件中断并清除待处理状态，再移除回调，之后才处理编码和 NVS。回调移除失败会明确记录错误，不显示学习成功，硬件中断仍保持关闭。硬件说明记录 GPIO5 已有 11 kΩ 外部上拉，不能仅凭拆除接收管就认定引脚悬空；非学习期间关闭中断用于避免无用的边沿处理，节电效果待实测。

红外学习按 10 μs 单位保存完整解调时序，最多 960 段、总时长不超过 750 ms。捕获使用 `esp_timer_get_time()` 计时，保存尾部空闲段；超限、无效波形或保存失败均报错，保留旧编码。学习流程及 NVS 格式保持兼容，无需重新学习；AP 开启时使用 I2S WS + FRC1，AP 关闭时使用 GPIO14 软件载波。清理失败会报错并阻止自动休眠。

DS18B20 的复位和逐位读写使用 RTOS 临界区保护。关键时隙函数放在 IRAM，直接读写 GPIO4 寄存器，按构建配置（当前固定 80 MHz）的 CPU 计数器等待各边沿和采样点，避免临界区内的 GPIO API 和 Flash 延时函数带来缓存等待。读位在起始后约 13 μs 采样；计数器差值支持回绕。临界区不覆盖 750 ms 转换等待，也不在其中输出日志；CRC 失败仍报错，不采用旧温度代替有效读数。主机模拟与链接检查不能代替实际 1-Wire 波形和休眠后测温验证。

发送取得忙碌标志和独立休眠锁后，根据 `portal_is_on()` 固定本次路径，日志标记 `backend=i2s/software`。发送前输出编码校验值、恢复 GPIO14 推挽输出并等待 UART 发完；帧内不输出诊断日志。AP 开启路径保留原有 I2S WS + FRC1，不使用 DMA，也不通过 `GPIO_IN` 回读作为发送成功门槛。

AP 开启路径通过 SDK 已链接的 `rom_i2c_readReg_Mask` / `rom_i2c_writeReg_Mask` 保存、使能并读回音频时钟位，仅操作 block `0x67`、host `4`、register `4` 的 bit `7`；定义依据为 [ESP8266 Arduino 的 I2S_CLK_ENABLE](https://github.com/esp8266/Arduino/blob/master/cores/esp8266/esp8266_peri.h)。`audio clock: before=... enabled=...` 记录保存值及使能后读回值；使能验证失败明确报错。停止 I2S 后恢复原值；停止或恢复失败保留原值及休眠锁，后续重试成功再释放。已有未清理的 I2S 状态不能通过软件路径绕过。

AP 关闭路径直接跳过音频时钟读写、I2S 配置和启动，不先尝试使能再回退，也不调用 `phy_open_rf()` 或开启热点。先停止 FRC1、将 GPIO14 拉低，再在整帧 RTOS 临界区内按保存的包络输出软件载波。关键函数及调用链在 IRAM，直接写 GPIO 寄存器，按构建配置（当前固定 80 MHz）的 `ccount` 累计截止时间计时；周期为 `round(cpu_mhz * 1000000 / frequency_hz)`，高电平占约半周期，支持 36/38/40 kHz。末尾不完整载波周期在包络截止时截断。保留现有段长和总长范围，最长 750 ms 内普通 RTOS 中断及按键处理会延后；NMI 看门狗保持启用。

软件发送记录 `late_cycles`，为边沿或包络结束相对截止时间的最大迟到 CPU 周期数；当前 80 周期为 1 μs。超过 400 周期（5 μs）时立即拉低输出并返回 `ESP_ERR_TIMEOUT`，不计入成功发送间隔，后续有效采样可重试。5 μs 是软件故障检测阈值，不代表实测精度。发送结束或失败均退出临界区、拉低输出并停止 FRC1；只有整帧完成且清理成功才返回 `ESP_OK`。FRC1 ISR 在软件路径不操作包络或 GPIO mux。

历史实机日志将 AP 关闭后的失败定位到 `stage=clock-enable`：音频时钟置位后读回仍为 0，实际包络为 `segments=0/140`。底层时钟为何不能恢复尚未确认；软件路径绕过该阻断，用户已于 2026-10-06 确认此前 160 MHz 软件载波实机验收成功；已有 80 MHz 基线的 AP/休眠红外正常反馈，最新定时器暂停与温度校准构建仍待完整实机验收。两条路径均保留 `esp_sleep_lock()` / `esp_sleep_unlock()` 独立保护，清理失败保留锁，后续清理成功释放，避免重复加锁；两条路径均不因发送改变 RF 状态，自动成功发送仍按每组至少 120 秒计时。

最近一次发送的返回值、路径、阶段、包络完成段数、最大迟到周期数及 I2S 时钟状态留在 RAM，下次采样前通过 `previous send` / `previous clock` 输出。`seq` 为发送序号；多次发送只保留最近一次，断电或复位不保留。软件路径输出 `previous clock: not used`，时钟字段内部为 `-1`，不冒充使能或恢复成功。`stage=envelope result=ESP_ERR_TIMEOUT` 在软件路径表示时序迟到，在 I2S 路径表示等待包络完成超时；清理错误另列。`carrier configured` 和 `software carrier configured` 中的 `calculated` 均为配置计算频率，不是实测频率。`send complete` 或 `ESP_OK segments=140/140` 只代表发送流程及清理完成，不能证明空调已接收。

主机测试分别以 80/160 MHz 编译，覆盖启动频率不匹配、实际源码的 GPIO 边沿、三种载波配置、整帧包络、750 ms 边界、计数器回绕、模拟 NMI 延迟、清理失败重试、NVS 编码保存及两组 120 秒间隔；模拟结果和链接检查不能证明硬件输出准确。实机验收以空调实际响应为准，用户已确认此前 160 MHz 软件载波验收成功；80 MHz 基线也已收到 AP/休眠红外正常反馈；最新构建及所有遥控协议、三种载波配置的完整兼容性仍待验收。

## 休眠与供电

正常测温间隔和 S2 休眠温控使用 SDK 自动 light sleep，定时唤醒采温及发送红外，完成后继续休眠。热点关闭期间通过 SDK 的 `phy_close_rf()` 关闭 RF，包括测温和红外处理时；开启热点前通过 `phy_open_rf()` 恢复 RF。热点开启、1-Wire 通信、红外学习或发送期间保持 CPU 唤醒。每次测温先检测 DS18B20 供电：独立供电、热点关闭且红外空闲时，GPIO4 切为输入，由板上 4.7 kΩ 上拉维持 DQ 高电平，转换等待允许休眠；读取前关闭自动休眠并恢复开漏输出。RF 开关流程已纳入主机测试，实际电流和休眠唤醒后的 RF 状态仍需实机验证。

转换等待保持 750 ms，并额外等待一个 tick 防止提前读取；转换前核验并确保 12 位分辨率。寄生供电时输出一次警告，保持唤醒等待，不提供强上拉支持。主任务等待下一次采样期限，按键通知可提前唤醒；单次上限按 CPU 频率保留 32 位计时余量，80 MHz 下不再拆成 10 秒等待，160 MHz 回退时最多约 25.84 秒。实际睡眠时长仍由 SDK 调度器决定。休眠配置失败后尝试关闭自动休眠并继续温控；若已启用的休眠无法关闭，则中止运行并报错。

本项目使用 LIR2450 锂电池，容量约 120 mAh。电池端功耗测量、按键和连续运行验收见 [功耗验收](tests/功耗验收.md)。当前节电比例与续航尚未确认。

休眠诊断使用现有链接包装机制，在 RAM 中累加，随测温采样、间隔至少 30 秒输出两行 `sleep_trace`；不增加任务、定时器、RTC 校准或休眠锁。`auto` 是 SDK 自动入口次数，`auto_no_hw` 是入口返回前没有低层尝试的次数；`hw` 是低层尝试，`hw_ok` 仅表示原函数返回 0，`hw_reject` 是硬件报告拒绝的次数。这些次数及 `bad_cal`、`zero_rtc` 均为本窗口增量；窗口可能跨越未完成的入口，不能要求计数严格相加。

`rtc_call_est_ms` 是本窗口未报告拒绝的低层调用前后 RTC 区间估算，使用本次 SDK 校准值，包含进入/退出开销，不使用尚未补偿的系统时间计量睡眠。`bad_cal` 和 `zero_rtc` 分别表示因缺少有效校准或 RTC 未推进而跳过估算的次数；`max_est_ms_total` 为启动以来单次最大估算值，`last_reject` 为最近一次非零返回值。`reasons=unavailable` 表示不能区分 SDK 内部锁、模式、GPIO 和期限等提前退出原因。统计及其与 `window_ms` 的比值不能作为精确睡眠时长或占比；诊断日志本身也有耗电，电流对比须保持相同诊断配置。操作步骤见 [功耗验收](tests/功耗验收.md#休眠统计验收)。

当前构建开关定义在 `main\Kconfig.projbuild`，默认值在 `sdkconfig.defaults`；已有 `sdkconfig` 不会自动同步。改变开关后须重新构建并核对生成配置。

| 配置 | 当前默认值 | 行为与限制 |
| --- | --- | --- |
| `CONFIG_APP_PAUSE_NOISE_TIMER` | 开启 | RF 关闭后取消 SDK 噪声定时器并阻止重登记，AP 启动前恢复；仅实际软件定时器队列为空时忽略旧 FRC2 alarm，保留计数及唤醒时钟补偿 |
| `CONFIG_APP_PAUSE_NETWORK_TIMERS` | 开启 | AP 关闭后在 TCP/IP 线程同步暂停周期及按需 TCP 定时器，开启前恢复；保留一次性超时，暂停期间网络状态不按周期老化 |
| `CONFIG_APP_DISABLE_DHCP_CLIENT_TIMERS` | 开启 | 构建时移除 DHCP 客户端 fine/coarse 周期项，保留 DHCP 服务端；仅适用于当前 AP 用途，增加 STA 前须关闭并重验 |
| `CONFIG_APP_QUIET_UART` | 关闭 | 开启时初始化后关闭运行日志并将 GPIO1 切为输入；排错需关闭并重新构建 |
| `CONFIG_APP_IDLE_BOOT_PINS` | 开启 | 初始化后释放 GPIO0/15 为无内部上下拉输入，依赖板上外部启动电阻 |
| `CONFIG_APP_SENSOR_IDLE_INPUT` | 开启 | GPIO4 初始化、转换启动失败或读温完成后释放为输入，下一次事务恢复开漏 |
| `CONFIG_APP_TEMP_OFFSET10` | 0 | 在原始温度舍入前应用 0.1 ℃整数偏移，未取得稳定偏差时保持 0 |

定时器恢复/停止失败明确返回错误；网络停止失败时不暂停其定时器。诊断随原采样汇总，不新建任务或周期定时器：最近最多 4 次低层调用记录 RTOS/FRC2 期限与 RTC 区间，`frc2_pending` 表示实际 SDK 软件定时器队列是否非空；最多 16 个 `wait_task` 组合只记录大于 0 且不超过 1 秒的请求等待，零等待、长/无限等待及溢出分别计入 `filtered_zero`、`filtered_long_or_infinite`、`dropped_full`。这些记录不是实际超时或真实唤醒原因，调用地址必须用同一镜像 ELF 解码。`noise_timer` 与 `network timers paused/resumed` 日志用于检查暂停、恢复和剩余队列，具体步骤见 [功耗验收](tests/功耗验收.md)。

## 构建与烧录

在仓库根目录使用 PowerShell：

```powershell
python build.py
python flash.py --port COM3 --dry-run
```

构建脚本扫描 `main` 的 C 源文件并更新组件源文件列表，临时映射空闲的 `Z:`，使用 CMake 和 Ninja `-j 12`，产物位于 `build\auto\`。SDK 可通过 `IDF_PATH` 覆盖，工具路径见 [编译环境说明](ESP8266编译环境路径.md)。从其他目录运行时使用脚本的绝对路径。

`sdkconfig.defaults` 设置 CPU 固定 80 MHz、晶振与 Flash 各 26 MHz、`CONFIG_PM_ENABLE=y`、HTTP 请求头上限 2048 字节和 URI 上限 1024 字节。已有 `sdkconfig` 不会被 defaults 覆盖，须同步选择 80 MHz；实际参数以构建生成的 `sdkconfig.h` 和 `flasher_args.json` 为准。

项目 `components\esp_http_server` 覆盖 SDK 的路由、解析和 socket 错误处理，其余实现、头文件及 Kconfig 继续使用指定 SDK。末尾 `*` 匹配剩余路径，`/generate_204_*` 探测重定向至控制页，`/mmtls/*` 的 GET/POST 返回 404。不支持的协议起始字节直接关闭连接，以 INFO 记录原因；HTTP 解析失败返回错误并关闭连接，收发错误保留真实 `errno`。

dry-run 只检查布局，不打开串口、不写 Flash。实际接线与烧录命令见 [工具说明](tools/README.md)；分段偏移以本次构建为准。完整 4 MB 镜像的未使用区域填 `0xFF`，整片写入会清除 NVS；保留规则和编码时使用分段烧录。
