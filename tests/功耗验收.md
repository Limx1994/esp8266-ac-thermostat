# 锂电池功耗验收

适用版本：0.1G（2026-10-05）。软件测试与产物记录以 [本地发布说明](../RELEASE.md) 为准；本文件定义实机验收，不将软件通过视为功耗已达标。

## 固件行为与验收边界

热点关闭时每 30 秒测温，热点开启时每 2 秒测温；开机首次立即测温。正常灭灯，仅热点开启时每秒亮 500 ms。正常测温间隔及 S2 暂停状态使用 SDK 自动 light sleep，保留唤醒后的 160 MHz CPU 频率和原有硬件。每段主任务等待最多 10 秒，用于限制 SDK 计时补偿范围，不改变测温周期。

2026-10-05 追加纯软件优化：测温先检测 DS18B20 供电。独立供电、热点关闭且红外空闲时，GPIO4 切换到输入，由板上 4.7 kΩ 上拉维持高电平，转换等待期间允许自动 light sleep；读取前关闭自动休眠、恢复开漏输出。保留原有分辨率配置和 750 ms 最大转换等待，额外等待一个 tick 避免提前读取。寄生供电时输出一次警告，保留唤醒等待，不新增强上拉支持。热点从未使用时 3 分钟关闭；访问页面或操作配置 API 后，按最后一次操作起空闲 10 分钟关闭。状态轮询及系统/后台探测不延长超时，红外忙碌时延后关闭。

正常自动休眠不得清空规则基线、触发状态及回差；从 S2 暂停状态恢复、重新配置规则或学习编码时沿用首次有效读数只建立基线的行为。30 秒周期可能漏掉两次采样间的短暂越界；持续越界在基线已建立后应在约 31 秒内被检测到，另计红外发送时间。

两组规则及红外编码沿用原有 NVS blob 布局；0.1G 新增共用载波键，旧数据无该键时使用默认 38 kHz。HTTP 状态新增电池字段并新增载波配置 API；学习只需组号，发送统一使用当前共享载波。I2S 或定时器清理失败必须报错，并阻止自动休眠；自动休眠配置失败后尝试关闭并继续温控，不反复重试，若已启用的休眠无法关闭则中止运行。配置 API 返回成功不代表芯片已经进入休眠。

## 软件检查

在仓库根目录使用 PowerShell；每条命令成功后再执行下一条：

```powershell
python build.py
New-Item -ItemType Directory -Force build_ascii | Out-Null
& "D:\APPS\Espressif\tools\ninja\1.9.0\ninja.exe" -f tests\build.ninja -j 12
.\build_ascii\rules_test.exe
python tests\test_power.py

python -m unittest discover -s tests -p test_flash_port.py
node --check tests\check_page.js
node tests\check_page.js
python flash.py --port COM3 --dry-run
git diff --check
```

确认生成的 `build\auto\config\sdkconfig.h` 包含 `CONFIG_PM_ENABLE`，CPU 为 160 MHz，Flash 与晶振为 26 MHz。已有 `sdkconfig` 必须同步启用 `CONFIG_PM_ENABLE=y`，defaults 不覆盖已有设置。主机测试使用 mocks，只验证实际代码的控制流程和错误处理，不验证实际硬件时序与电流。

主机测试覆盖独立/寄生供电检测、命令顺序、DQ 输入及开漏切换、CRC、负温度和 GPIO 错误；控制测试覆盖转换等待中的按键、供电/休眠失败回退、规则状态保持、3/10 分钟热点超时及红外忙碌延后关闭。历史阶段的通过记录不代替 0.1G 本轮重跑；最终应用大小和验证结果集中记录在 [RELEASE.md](../RELEASE.md)。

## 电池端测量

比较同一块板、相同电池电压、相同规则及红外编码下的原固件、第一阶段固件和最终固件。第一阶段只改 LED、普通测温日志及 I2S 启停，保留 5 秒测温；第二阶段加入热点关闭时 30 秒测温和自动休眠；当前热点开启时改为 2 秒测温。测试前记录固件来源、构建参数及电池电压。

断开 USB-C 及可能反向供电的 USB-UART，在电池与整机之间测量电流。电源或电流仪须支持热点和红外发送瞬态，避免测量接线压降引发复位。需要查看日志时单独进行功能验证，再断开串口进行电流测试。默认不输出普通测温日志，不在功耗对比过程中开启 DEBUG。

各运行状态至少记录 10 分钟平均电流，同时保存电流波形，确认测温后确实出现持续低电流区间；红外另记录发送峰值及单次积分电量。热点开启状态分别测手机未连接、手机已连接并打开页面，不涉及多客户端。

| 状态 | 原固件平均电流 | 第一阶段平均电流 | 最终平均电流 | 条件/结果 |
| --- | --- | --- | --- | --- |
| 热点关闭、正常监测、无红外触发 | 待测 | 待测 | 待测 | 相同电池电压与环境温度 |
| 热点开启、手机未连接 | 待测 | 待测 | 待测 | 同时记录前 3 分钟热点电流及至少 10 分钟整体平均电流、关闭时刻 |
| 热点开启、页面打开 | 待测 | 待测 | 待测 | 单手机、相同页面操作 |
| S2 暂停 | 待测 | 待测 | 待测 | 灯灭、不测温、不发红外 |
| 同一红外编码发送 | 待测 | 待测 | 待测 | 另记录峰值及单次电量 |

优先比较热点关闭监测的平均电流是否下降，再结合实际热点开启比例、发送次数估算续航。只有电池端平均电流可直接用于 `续航小时 ≈ 可用容量 mAh / 平均电流 mA`；不得用 3.3 V 输出电流直接代替电池电流，也不得把芯片手册的睡眠电流当作整机电流。

当前产物位于 `build\auto\`，追加优化检查点位于 `build\power_opt_checkpoint\stage1\` 和 `stage2\`，后者包含 `conversion_sleep.bin`。这些目录不随 Git 分发，检查点不替代已确认版本的对照固件。历史文档提到的 `build\power_stage1\` 与 `build\power_checkpoint\` 当前已不存在；需要对比时应先准备并记录可追踪的对照镜像。11 bit 降分辨率方案未实施。

## 实机功能验收

- 测温：开机立即测温；热点关闭约 30 秒一次，开启约 2 秒一次；持续越界后按期触发，两组规则只发送一次，反向回退 0.5 ℃ 后才重新触发。
- 休眠：多次正常自动休眠后规则状态仍保留，不因每次唤醒重建基线；DS18B20 拔除或 CRC 错误时停止自动发送，恢复后首次有效读数只建立基线。
- 转换等待：确认 DS18B20 独立供电检测结果；在转换等待期间观察低电流区间，唤醒后读数及 CRC 正常，GPIO4 恢复开漏通信。GPIO 切换失败或传感器拔除时上报错误且不发送红外。
- 按键：正常监测中 S1 随时唤醒并开热点，再按 S1 提前关闭，关闭后可再次开启；S2 暂停温控，暂停后分别测试 S1/S2 恢复。转换期间按键仍需等待转换完成才处理，约 750 ms 加一个 tick，再计其他处理时间；不得提前读取转换结果。长按只产生一次操作，松开后可再次使用，短按和抖动不导致连续切换。
- 热点：手机连接、弹页、保存配置、测试发送正常；未使用 3 分钟关闭，使用后从最后操作起空闲 10 分钟关闭，状态轮询及系统/后台探测不延长超时；重新开启热点恢复未使用的 3 分钟期限。学习和发送期间按 S1 请求关闭，完成后关闭并恢复低电流，请求等待期间再按 S1 可取消。手动关闭后恢复 30 秒测温并保留规则状态。
- 红外：两组编码分别验证 36/38/40 kHz；用目标空调及逻辑分析仪核对载波和重放波形，发送完成或超时后 GPIO14 为低、I2S 停止。
- 稳定性：连续运行至少 24 小时，记录实际测温周期、计时漂移、复位及异常日志，排除漏触发、重复发送和任务异常；重启后规则、编码及共享载波设置保持。

## 当前实机状态

历史用户日志和反馈曾确认旧构建的 Android 自动弹页及红外学习保存、发送日志，不能代表目标空调响应或当前固件验收。0.1G 本轮未烧录，未执行电池端电流测量、实机按键/热点/传感器/红外验收或 24 小时稳定性测试，节电比例和续航尚未确认。硬件未修改；GPIO2 实际 LED 接线、TPS63031 的 PS/SYNC 电平及 HS0038B 常供电消耗需实测或查图。GPIO16 未接 RST，本轮不采用 deep sleep。
